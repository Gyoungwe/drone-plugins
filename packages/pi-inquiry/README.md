# pi-inquiry (private migration candidate)

This unpublished combined package supplies an official Pi extension, an installed Desktop panel and the optional `inquiry.runtime@1` provider. All three use the same canonical Inquiry SQL and ledger owner. SQLite file format, project identity and original bytes remain preserved. The candidate must not be published or described as a complete migration: legacy host event/rerun composition, workspace promotion and formal packaged GUI acceptance remain unfinished.

The Desktop manifest requests independent JSON metadata and binary state directory grants. Select the same original ledger directory for both grants, then explicitly bind existing data to the actual workspace. The native Pi entry defaults to `<canonical workspace>/runs/.drone-inquiry`; it does not silently adopt a different Desktop data directory. A trusted Node adapter may select an existing directory through `nativeInquiryExtension` options. Every native write displays the actual workspace, SDK session and affected bytes/metadata through the real SDK confirmation UI. No UI means no native write.

The panel and native `inquiry_read` / `inquiry_write` tools share actual scoped operations. The tool input wraps the operation in `{ "request": { "action": "status" } }`. Explicit `recordComputeEvent`, `recordTaskTerminal` and `recordLocalExecution` writes run the preserved event projector inside the same SQLite CAS transaction. They accept validated ordinary JSON and remain plugin-asserted; supplying a session ID, hash or provenance in those records grants no execution or storage authority. Actual background automatic dispatch still awaits the scoped private-origin transport.

Available operations include explicit binding, original SQLite inspection, all ledger record types, provenance, decision review, pending-rerun inspection, reconciliation and exact original restore. Records remain plugin-asserted or imported data, not independent host provenance proofs. Rerun execution and workspace promotion are explicitly unavailable until their real provider/file ports migrate.

Each write requires actual caller authorization, a cross-process writer lease, raw-byte CAS and readback. SHA-named original backups are immutable. Pending metadata or database writes require explicit reconciliation; cancellation after a commit never implies unchanged bytes. Active WAL/SHM/journal files, external changes and databases over the fixed 4 MiB boundary are refused. Cleanup failure retains the writer lease for explicit recovery. Desktop JSON uses the host's real JsonStore; native Pi uses the public Node binary/CAS helper to persist its own bounded JSON metadata atomically, with strict corruption handling and readback. These adapters are distinct and are tested separately.

`npm run check:domain` checks canonical Node/WASM SQL, original-byte persistence and provider behavior. Build artifacts include the real sql.js loader/WASM/license; no Node SQLite is imported by the managed domain. Installed tarballs additionally require actual SDK and rendered UI acceptance in Drone. Current fixtures cover native approvals/late cancellation/shutdown, managed native/UI shared ownership, restore, and legacy-writer handoff. Formal DMG GUI remains `NOT_RUN` for this candidate.

Boundary checks in the native adapter validate actual SDK context, filesystem identity, root-relative paths, public JSON/base64 inputs and external IO outcomes. Errors propagate; the only fallbacks are explicit missing-file results. Shutdown collects failures so it cannot release a lease after incomplete cleanup.
