## 1. Binding decisions and candidate versions (#1)

**User decision:** freeze/import/fork each require a fresh `application-state-write` action; export requires its own exact export confirmation. Imported JSON never grants authority. Keep v1 capsules and the 64 MiB cap; public/restricted exports expose hashes/timestamps plus audience-permitted blobs and are verify-only; authors classify, hosts validate. Adopt original roots only by explicit grant, old-writer drain, lease handoff and identity/byte readback; retain data on disable/uninstall, re-adopt on reinstall, never move/delete it. Executable Evidence replay is unavailable; `verifyReplay` only compares.

**User decision:** critics use a genuinely independent host-resolved provider, enforced read-only execution and separately approved spend. Multipath/evaluation use one reviewed batch, individual budgets/host receipts and cancellation of remaining work. Export reviews the exact script/notebook bundle, prevents symlink escape and reads every file back. Automatic Inquiry facts must originate in the host; asserted JSON remains asserted; task completion means an accepted task event. Inquiry owns durable rerun decisions; host owns authorized submit/status/collect. Reuse only `application-state-write`, existing compute preflight and `background-model-spend`; credentials/model resolution stay host-only, requested by profile. Remove shared algorithms after callers migrate; retain type-only aliases until Plugin API 2.0.

## 2. Routing and service ownership (#2)

Use the existing installed-source pattern: schema/result/effect registration (`packages/pi-knowledge/src/desktop/cloud-runtime.ts:12`), closed objects (`packages/pi-knowledge/src/desktop/cloud-contract.ts:35`) and manifest provision (`packages/pi-knowledge/plugin.manifest.json:33`). Contracts/types/schema values shared by packages belong in **new API exports** `@gyoungwe/plugin-api/p5-evidence`, `/p5-discovery`, `/p5-inquiry`, `/p5-receipts`; these are proposed export names, not existing files in this repository. Package-local contract modules below only select these schemas and adapt local domain types; they must not duplicate the shared definitions or import a provider package.

Manifest proposals: Evidence provides `evidence.runtime@1`; Analysis requires alias `evidence` for that service. Discovery provides `discovery.runtime@1`, adds alias `inquiryRecords` for **new** `inquiry.discovery@1`, and retains its current `inquiry` → `inquiry.runtime@1` until its callers migrate. Inquiry provides the new record service alongside existing `inquiry.runtime@1` (`packages/pi-inquiry/plugin.manifest.json:8`). New operations are additive; do not tighten or change existing `inquiry.read/write` result shapes in place. A service's operation list is exactly its rows below. UI uses its own installed runtime client, never a provider catalog.

Every cross-plugin call is `provider.inspect({alias})`, then `provider.read/write({alias,operation,input})`; the host binds actual caller/source hashes, workspace/session, provider generation, cancellation and owner lease. No provider IDs, roots, model selections, callbacks or approvals can be supplied as authority in JSON. Routing/version/ambiguity rules already exist (`docs/PLUGIN-SPEC.md:188`, `node_modules/@gyoungwe/plugin-api/dist/runtime.d.ts:346`). Revalidate on dispatch, reject cycles and drain nested calls before owner release. Standard native Pi reports unavailable when a host routing capability is absent; do not add a global registry or duplicate runtime.

Host operations additionally needed: `model.critic.review` uses `CriticInput → CriticResult`; `execution.batch.run`, `execution.batch.status`, `execution.batch.cancel` use the corresponding batch row schemas; `files.writeBundle` uses `BundleInput → BundleCommit`; `facts.read` uses `CollectInput → FactsResult`; `compute.rerun.submit`, `compute.rerun.status`, `compute.rerun.collect`, `compute.rerun.cancel` use `ComputeRerunInput` for submit and `RequestInput` otherwise, returning `ComputeRerunResult`; `receipts.read` uses `ReceiptInput → Receipt`. Each returns the same failure envelope. Effects/approvals follow the corresponding table rows; `facts.read`/`receipts.read` are read/no approval. These are **proposed host capabilities**, absent from the cited installed declarations, not commands available today.

`ExportSource.text` is for bounded script/notebook content; Evidence capsules use an immutable staged file reference produced by the P0 byte-file adapter, so a 64 MiB capsule is not forced through a small JSON message. The host verifies staged hash/bytes, current owner/caller and action scope before including that file in the exact export review. A copied `fileRef` cannot convey approval. P0 must specify the byte-stream adapter's own transport schemas before dispatching the owner; this document freezes the cross-plugin service wire, not an uninspected host filesystem implementation.

Host receipt references must resolve in the durable host broker under the actual caller/provider/source generation. `receipts.read` never accepts caller-selected identity or an imported receipt object. Store receipts for approval denial/no invocation, acceptance before external submission, per-item execution/spend, cancellation/cleanup and each file readback. Failed/unknown outcomes cannot claim success. Persist domain decisions plus host receipt references atomically, then return the actual readback SHA; do not embed a document's own raw hash in itself. Redact secrets/content from audit receipts. Host execution/model payloads are transient and excluded from those receipts. Reuse the existing transaction/storage mechanisms, not another receipt authority.

### Ticket-specific semantics

**9 — preparation/owner:** `analysis.prepareEvidence` calls the existing plan constructor (`packages/pi-analysis/src/evidence-plan.ts:25`), then `evidence.plan.validate` using the same plan schema as the validator (`packages/pi-evidence/src/analysis-plan.ts:51`). It accepts an adapter plan as data, never execution proof. Freeze independently resolves `runReceiptRef`, observed files and current analysis from the host; mismatched plan/source/bytes fail. Host assigns time/causality; checkpoint identity remains lineage-invariant (`packages/pi-evidence/src/checkpoints.ts:88`). Access assignments must cover every artifact/version exactly once. Native pure validators remain available without managed storage.

Adopt existing analysis runs and Evidence ledger/blob/branch/capsule roots in place. Reuse the host's existing JsonStore/file/lease ports; no plugin-side default root guessing. State JSON uses CAS/atomic write/readback; byte blobs and branch materialization use a confined host file transaction scoped by that action's state-write approval, never `state.writeJson` on arbitrary files. Existing binary state is capped at 4 MiB and file binary snapshots at 8 MiB (`docs/PLUGIN-SPEC.md:263`, `docs/PLUGIN-SPEC.md:269`); do not claim they transport a 64 MiB capsule. A host file-reference/streaming adapter preserving the total 64 MiB cap is a prerequisite. Import resolves an approved `sourceFileRef`, verifies exact v1 bytes and rejects attestations (`packages/pi-evidence/src/capsule.ts:240`). Export produces private v1 capsules or public/restricted hash-only v1 attestations (`packages/pi-evidence/src/capsule.ts:15`); metadata redaction and audience-filtered blobs are preserved. Fork never restores authorization; failures preserve existing data and report any newly owned temporary cleanup failure. No recursive deletion/retry cleanup of adopted data. `verifyReplay` compares recorded output metadata/environment only (`packages/pi-evidence/src/replay.ts:49`); no executable replay operation is registered.

**11 — critic:** the host binds `primaryRunReceiptRef` to the finding's actual producing run, rejects unrelated references, resolves `profile` and the primary provider, compares actual provider identities before model invocation, installs no shell/write/network/delegation tools and separately approves `background-model-spend`. The plugin cannot choose `primaryProviderId` as authority; local policy alone (`packages/pi-discovery/src/domain/critic.ts:59`) is insufficient. Return denial/independence receipts with zero invocations; preserve blocked/timeout behavior. Journal review readback precedes `inquiry.discovery.record`; deterministic question IDs allow completion of a failed Inquiry leg without another model call. Inquiry maps closed question data to its canonical QuestionRecord with the bound project, timestamps and existing priority policy. The old `recordDiscovery` path remains until its question/attempt/finding callers have migrated; this new narrow operation does not silently drop that separate finding behavior (`packages/pi-discovery/src/service.ts:182`).

**12 — batches:** item IDs must bijectively match paths/cases; host freezes exact request, resolved profiles/cached images, preflight hashes and per-item budgets in one review. There is no executor callback in JSON. Compute items use existing compute preflight, model items additionally use `background-model-spend`; unknown usage/cost stays unknown and cannot justify further spending against a monetary cap. No automatic retry/resubmission. Cancellation/disable stops scheduling, cancels active owned work, waits for cleanup, retains all per-item receipts and commits only under a still-authorized caller. Within one ledger-owner transaction, project facts and advance the cursor only after original SQLite CAS/readback. Dedupe by host fact ID plus content hash; changed content under the same ID is `DUPLICATE_CONFLICT`. Sequence numbers are host-monotonic per workspace; drain in order, buffer a gap without marking it consumed, reject cross-session delivery and stale terminal downgrades. **15 — rerun recovery:** persist an intent keyed by request ID/source artifact SHA before host submission. Host accepts one idempotent submit for that exact request hash under existing compute preflight, records acceptance durably, and can find it by request ID even if response/persistence failed. Inquiry then commits submitted/job receipt; if that commit fails, return `PERSISTENCE_PENDING`, recover by status, never resubmit. On a hash-conflicting duplicate return `DUPLICATE_CONFLICT`. Status is read-only; collect is a new authorized ledger mutation using host-verified terminal receipt/artifact bytes. Preserve submitted→running→reproduced (same hash), superseded (different hash), failed (execution/collection/cancel/budget failure), matching current model states (`packages/pi-inquiry/src/models.ts:214`). Reuse the same original SQLite/owner (`packages/pi-inquiry/src/ledger-owner.ts:127`), not a new JSON rerun ledger.

Inquiry's durable intent stores budget, host refs and cancellation/recovery state beside its existing rerun decision, never credentials or grants. Cancel records intent before host cancel, stops new work, awaits owned cleanup and then commits failed with `CANCELLED`; cleanup failure remains visible/pending. Disable aborts owned work and drains without borrowing a new session; if no valid write caller remains, leave durable host outcomes for explicit reconcile after re-enable. Restart queries pending submitted/running jobs once on activation/explicit refresh; no automatic resubmission or recurring polling setting. A late/duplicate completion cannot revive a cancelled/terminal record; changed results are surfaced for explicit reconciliation. Collection must recheck the source artifact SHA and bound workspace; old outputs stay intact. Reinstall re-adopts pending records and queries host receipts; restored JSON cannot resume spend. No replay executor is enabled by this rerun contract.
